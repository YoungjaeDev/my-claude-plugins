# RECOVERY

## 기본 원칙

검증이 실패하면 곧바로 광범위한 수정에 들어가지 않는다. 진단부터 한다.

## 실패 루프

검증 단계가 실패하면 다음 순서를 따른다.

1. 실패 출력을 끝까지 읽는다.
2. 실패 유형을 분류한다: 구현 버그 / 잘못된 테스트 / 의존성 누락 / 환경 문제 / 요구사항 불명확 / scope 충돌.
3. PRD.md, PLAN.md, VALIDATION.md와 비교한다.
4. 가장 작은 가역 수정 1회를 한다.
5. 가장 작은 관련 검증부터 재실행한다.
6. PROGRESS.md를 업데이트한다.

## 재시도 한계

같은 검증이 서로 다른 3회(3 attempts) 시도 후에도 실패하면:

골이 진단·검토 모드로 전환되고 자체 수정을 멈춘다. Claude Code 는 `/goal pause` 를 지원하지 않으므로 사람의 결정을 기다린다. 필요하면 `/goal clear` 후 재설정한다.

다음을 보고한다.

- 실패한 명령 또는 기준
- 시도한 3가지 수정
- 각각의 실패 이유
- 다음으로 안전한 옵션
- 사용자·제품 결정이 필요한지 여부

## scope 잠금

다음은 금지한다.

- 무관한 모듈을 다시 작성
- PLAN.md에 명시되지 않은 public API 변경
- 검증을 통과시키기 위해 테스트를 삭제·skip
- 이해 없이 에러를 침묵 처리
- 좁은 문제를 광범위한 refactor 로 해결
- 검증 명령 자체를 다른 명령으로 교체

이 골에만 해당하는 추가 금지:

- **플러그인 흡수·rename 실행**: #198 영역이며 PR #200 으로 이미 끝났다. 되돌리기 어렵다. 흡수 결과를 *검수*하는 것(M2)과 흡수를 *수행*하거나 *되돌리는* 것은 다르다.
- **`docs/audit/` 기존 파일 수정·이동·삭제** — 과거 감사 기록이다. 새 산출물만 추가한다.
- **이력 표면을 grep 결과에 맞춰 고치기**: `.llmwiki/`, `tests/fixtures/`, 제거 안내 문구는 과거를 서술하므로 보존 대상이다. "0건"을 만들려고 이걸 지우는 것이 이 골의 가장 그럴듯한 오작동이다.
- **이미 번들인 플러그인 11개의 구조 변경**
- **skill-forge 본문에 외부 마켓플레이스 스킬을 읽으라는 지시 추가** — 자립 제약 위반이며 조용히 깨진다.
- **M0 의 미확인 항목을 확인 없이 규칙으로 단정** — 근거 없는 금지를 만든다. 확인 못 하면 `unverified` 로 표기한다.
- **전수 검토(50개 스킬) 착수** — 별도 이슈다. 이 골은 도구를 만들 뿐 아직 돌리지 않는다.

## 방향 재확인 규칙

접근법을 바꾸기 전에:

1. 골 문장을 다시 읽는다.
2. PRD.md의 Non-goals 를 다시 읽는다.
3. PLAN.md의 현재 마일스톤을 다시 읽는다.
4. 다음 수정이 현재 마일스톤에 직접 기여하는지 확인한다.

## 되돌리기 규칙

자기 자신의 마지막 실패 변경만 되돌린다. 단, 다음 중 하나일 때:

- 변경이 검증을 더 악화시켰을 때
- 무관한 변경을 함께 들여왔을 때
- PRD / PLAN 과 충돌할 때

사용자가 수동으로 만든 변경은 명시적 지시 없이 절대 되돌리지 않는다. 특히 PR #200 (흡수)의 결과물은 사람이 만들어 이미 머지된 변경이므로 검수 대상이지 되돌리기 대상이 아니다.
