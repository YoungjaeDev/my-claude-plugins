# Spec: llm-wiki v2 — curated-conservative upgrade + neutral `.llmwiki/` layout + Codex sharing

Date: 2026-05-29
Status: in-progress
Owner: YoungjaeDev

This spec is the **authoritative build contract** for the llm-wiki v2 implementation. Every
parallel module agent copies the canonical snippets below verbatim. When this spec and prose
elsewhere disagree, this spec wins.

## Context

`llm-wiki` v1.1.1 ships the Karpathy 3-layer system (schema / wiki-lore / raw). The rohitg00 v2
gist proposes a maximalist redesign (numeric confidence floats, Ebbinghaus decay, 4-tier memory
dirs, vector/BM25 search, event-driven auto-writes); the gist's own top comments reject that
blueprint for false precision, wrong decay model, and silent LLM corruption on auto-writes. We
harvest the lightweight, git-auditable kernel of each idea and reject the heavyweight parts.

Three problems solved:

1. Harvest the curated, human-gated kernel of each v2 idea.
2. **Codex fork bug**: `codex-bridge` rewrites `.claude/` → `.codex/` in skill bodies (literal
   transform rule in `codex-bridge.config.json`), so a skill naming `.claude/wiki/` becomes
   `.codex/wiki/` in Codex — forking the wiki per-agent. Fix = a neutral top-level root the
   transform's match set can never touch.
3. Existing v1 deployments (`.claude/wiki/` + forked `.codex/wiki/`) need an in-place migration.

Verified during planning:
- `.claude/rules/*.md` auto-load at session start (built-in, recursive; `paths:` glob = conditional
  load). The schema layer therefore stays pinned to `.claude/rules/`.
- The `.claude/` → `.codex/` transform is `{ "from": ".claude/", "to": ".codex/", "mode": "literal" }`
  and `bodyOnly: true`. `.llmwiki/` is not under `.claude/`, so the rule never matches it → inert.
- `SessionEnd` hook stdout is shown to the human only (NOT model-visible). `SessionStart` injects
  `additionalContext` into the model (like the existing UserPromptSubmit stale-check). **Decision
  (locked with user): the lint-overdue hint uses `SessionStart`**, superseding the plan's literal
  "SessionEnd" wording. Hook file: `wiki_session_start_lint_hint.sh`.

## §1 — Target layout & resolution order

```text
.llmwiki/                  NEW neutral root (codex-bridge .claude/->.codex/ never touches it)
  raw/                     immutable evidence (Evidence: may still cite external docs/)
    .gitkeep
  wiki/
    index.md   log.md
    <domain>/<page>.md
.claude/rules/             schema/invariants STAY (only verified auto-load path)
  _entrypoint.md           documents layout + memory overlay + resolution order
  code-map.md  _domain-*.md
.claude/{skills,spec,hooks}/  unchanged locations
```

**Resolution order** (every skill + hook): `.llmwiki/wiki/` → `.claude/wiki/` (legacy) →
`.codex/wiki/` (legacy fork). New repos get `.llmwiki/`; old repos keep working until migrated.

### §1.1 — Canonical wiki-root resolver (hooks, bash — copy verbatim)

```bash
# --- canonical wiki-root resolver (llm-wiki v2) ---
# Resolution order: .llmwiki/wiki (preferred) -> .claude/wiki (legacy) -> .codex/wiki (legacy fork)
# A candidate counts only if it carries an init signal (index.md or log.md), so an empty
# seeded .gitkeep-only dir never masks a populated legacy wiki.
resolve_wiki_root() {
  local cand
  for cand in ".llmwiki/wiki" ".claude/wiki" ".codex/wiki"; do
    if [[ -f "$cand/index.md" || -f "$cand/log.md" ]]; then printf '%s\n' "$cand"; return 0; fi
  done
  return 1
}
wiki_root="$(resolve_wiki_root)" || exit 0
```

### §1.2 — Resolution wording (skills, prose — use consistently)

> Operates on the repo's wiki root, resolved in order: `.llmwiki/wiki/` (preferred) →
> `.claude/wiki/` (legacy) → `.codex/wiki/` (legacy Codex fork). Examples below use
> `.llmwiki/wiki/`; substitute the legacy path if that is what the repo has.

Raw evidence lives at `.llmwiki/raw/` (preferred). `> Evidence:` cites may also point at any
external path (e.g. `docs/research/audits/<file>.md`) — raw is never copied into the wiki.

## §2 — v2 frontmatter schema (wiki PAGES only; index.md/log.md exempt)

```yaml
---
id: <kebab-case-slug>          # unique page identity
aliases: [other-names]         # dedup / search keys
last_verified: YYYY-MM-DD      # trust signal; bump ONLY after re-checking vs code/source
status: active                 # NEW: active | stale  (stale = kept+marked, never deleted)
volatility: stable             # NEW: stable | volatile  (drives staleness window; default stable)
sources: 2                     # NEW: integer count of named provenance under ## Sources
---
```

- `status` default `active`. A superseded page becomes `status: stale` + gains `> Superseded-by:`.
  Stale pages are KEPT, marked, linked, timestamped — never deleted.
- `volatility` default `stable`. `stable` (arch/design decisions) → 180-day staleness window;
  `volatile` (bug/transient/quirk) → 30-day window. Absent ⇒ treated as `stable` (180d).
- `sources` = number of distinct provenance entries listed under the page's `## Sources` section.
  This REPLACES numeric float confidence (no `0.85` floats anywhere). "How sure" = source count +
  `last_verified` recency + presence of `> Contradicts:`.

`index.md` keeps its `id: wiki-moc` minimal frontmatter; `log.md` has no frontmatter. Both are
excluded from staleness/volatility checks.

## §3 — v2 typed cross-ref grammar

Pages link only via typed blockquote refs — never a bare `[[wikilink]]` on its own line.

Existing (keep):
- `> Refines: [[id]]` — this page adds detail to another
- `> Contradicts: [[id]]` — conflict; resolve before next edit
- `> Evidence: .llmwiki/raw/<file>` — citation to immutable raw (or external `docs/...`)
- `> See-also: [[id]]` — related but independent

New — supersession (lifecycle):
- `> Supersedes: [[id]]` — on the NEW page, points at the claim it replaces
- `> Superseded-by: [[id]]` — on the OLD page (paired with `status: stale`)

New — typed relations (kills the flat-`related` failure mode):
- `> Uses: [[id]]`
- `> Depends-on: [[id]]`
- `> Caused-by: [[id]]`
- `> Fixed-by: [[id]]`

The `[[id]]` target inside a typed ref is allowed and expected. The lint "relationship" check flags
only a bare line starting with `[[` (untyped). Typed refs are never flagged.

## §4 — Volatility-window staleness (replaces flat 60-day)

Per page: read `volatility:`. `volatile` → window 30 days; `stable` or absent → 180 days. Compare
`age_days = (today - last_verified)` against the window. Used identically in `lint-wiki` staleness
scan and `wiki_stale_check.sh`.

## §5 — Memory overlay (light-tag of 4-tier; NO new directories)

Documented in `.claude/rules/_entrypoint.md` as a conceptual mapping onto existing artifacts:

| Memory tier | Maps to (existing artifact) | Lifetime |
|-------------|-----------------------------|----------|
| Working | the current session (ephemeral) | this conversation |
| Episodic | `.llmwiki/wiki/log.md` (chronological event log) | append-only |
| Semantic | `.llmwiki/wiki/<domain>/*.md` (consolidated lore) | long-lived |
| Procedural | `.claude/skills/*/SKILL.md` (workflows) | long-lived |

This is documentation only — no `working/`, `episodic/`, `semantic/`, `procedural/` dirs are created.

### §7.6 migrate-wiki (NEW — `skills/migrate-wiki/SKILL.md`)
- **Pushy description** triggering on: "migrate wiki", "upgrade wiki to v2", "consolidate .claude/wiki
  and .codex/wiki", "move wiki to .llmwiki". Universal.
- Procedure:
  1. **Detect** wiki(s) at `.llmwiki/wiki/`, `.claude/wiki/`, `.codex/wiki/`; report which exist +
     schema state (do pages have v2 frontmatter yet?).
  2. **Consolidate (optional)** per-agent copies → `.llmwiki/wiki/`. Dedup by `id`. On conflicts
     (same `id`, divergent bodies) present via `AskUserQuestion` — NEVER silent-delete. Keep the
     legacy dir until the user confirms removal (do not auto-remove).
  3. **Add v2 frontmatter defaults** to each migrated page: `status: active`; inferred `volatility:`
     (heuristic: page path/title/aliases matching `design|arch|architecture|decision|adr|rationale`
     → `stable`; matching `bug|debug|fix|race|quirk|transient|incident|flaky` → `volatile`; else
     `stable`); `sources:` counted from existing `## Sources` (0 if none).
  4. **Additive grammar only** — never rewrite existing cross-refs; only add new typed refs where
     clearly applicable.
  5. **Idempotent**; re-running on a v2 wiki is a no-op. Diff-log to resolved `log.md` FIRST
     (git-revertible), one `## YYYY-MM-DD — migrate v1->v2 (migrate-wiki)` entry listing every page
     touched, before applying edits.

### §8.3 wiki_session_start_lint_hint.sh (NEW — SessionStart)
- Read stdin JSON (don't block); resolve `wiki_root` via §1.1 (after optionally `cd`-ing to `cwd`
  from stdin if present — else operate on `$PWD`). If no wiki → exit 0.
- `log_file="$wiki_root/log.md"`; if missing → exit 0.
- Find newest lint date:
  ```bash
  newest=$(LC_ALL=C.UTF-8 grep -oP '^##\s+\K\d{4}-\d{2}-\d{2}(?=.*\(lint-wiki\))' "$log_file" 2>/dev/null | sort -r | head -1)
  ```
- If `newest` empty → hint "no lint-wiki baseline; consider /lint-wiki". Else compute age in days;
  if `> 3` → hint "last /lint-wiki was N days ago (DATE); consider /lint-wiki to catch drift".
- **Emit as SessionStart `additionalContext`** (model-visible):
  ```bash
  esc=$(printf '%s' "$msg" | sed 's/\\/\\\\/g; s/"/\\"/g')
  printf '{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"%s"}}\n' "$esc"
  ```
- Soft-hint only; NO wiki write. Rate-limit once per 4h per cwd via `/tmp` marker (avoid /clear spam).
- `set -u`, `exec 2>/dev/null`, exit 0 always.
