# 덱 제작 규칙

> 원본은 `deck` 플러그인의 `templates/rules/deck-authoring.md`다. 이 사본을 직접 고치지 말고 원본을 고친 뒤 `deck-sync`로 다시 받는다.

덱을 어떻게 만드는지 정한다. 무엇을 쓰는지는 `deck-copy.md`, 문장은 `korean-style.md`, 섹션 HTML 형식과 통과 기준은 `deck-author` 스킬에 있다. 덱마다 다른 사실은 `deck/outline.md` 머리말에 둔다.

**원고가 기준 · 디자인은 셸에 · 흐름은 움직임으로 · 화면은 목업으로 · 원문은 패널로 · 근거는 링크로**

## 원고가 기준

문구의 기준 원본은 `deck/outline.md`다. 머리말에는 덱의 주장 한 문장, 섹션 목록, 섹션 파일, 장 수, 명령의 기준 원본 파일, 배포 대상만 적고 규칙을 옮겨 적지 않는다.

- 문구·사실·구성은 원고를 먼저 고친 뒤 섹션 파일에 옮긴다. 빌더는 승인된 문구를 임의로 재작성하지 않는다.
- 윤문은 의미·수치와 HTML 구조를 보존하고 원고와 화면을 함께 갱신한다. dev 서버 편집 모드로 고친 문구는 원고에도 옮긴다.
- 요청받은 장 밖은 건드리지 않고 덱 전체를 다시 생성하지 않는다. 기존 장 사이에 끼우는 장은 앞 장 ID에 `b`를 붙인다(`S2-03b`).
- 고친 뒤에는 `deck-check`로 빌드·문구 검사·렌더를 돌리고 렌더 PNG를 직접 본다.
- 배포는 사용자가 로컬 확인을 마치고 명시적으로 요청할 때만 `deck-deploy`로 한다. 고칠 때마다 다시 배포하지 않는다.

## 디자인은 셸에

토큰·컴포넌트·글꼴은 `deck/shell.html`에만 둔다. 섹션 파일에는 CSS를 넣지 않고 inline `style`은 `deck-author` 허용 목록만 쓴다.

- RALPHDEV 브랜드를 쓴다. 글꼴은 직접 호스팅한 IBM Plex Sans KR Regular 400·SemiBold 600만 쓰고 합성 굵기를 만들지 않는다.
- 1920×1080 고정 스테이지를 유지하고 작은 화면에서 내용을 재배치하지 않는다.
- 표지 다음에 목표와 목차를 두고 섹션마다 섹션 표지를 둔다.
- 섹션 안의 장에는 `data-section`을 단다. 첫 섹션 앞의 소개 장과 닫는 장에는 달지 않는다.
- 셸 푸터가 RALPHDEV 워드마크와 Ralph 캐릭터를 넣는다. Ralph 캐릭터를 다른 마스코트로 바꾸지 않는다.
- 장식은 넣지 않는다. 제목 옆 세로 accent bar, 짧은 장식 막대, 장식용 그라데이션, 내용 없이 반복되는 카드·패널, 반복되는 슬로건이 그렇다. 구분선과 강조색은 진행 표시나 데이터 비교처럼 뜻이 있는 곳에만 쓴다.
- 마스코트와 픽셀 컷은 아껴 쓴다. 놓을 자리와 개수는 `deck-assets` 스킬이 정한다.

## 흐름은 움직임으로

누가 누구에게 무엇을 넘기는지는 다이어그램으로, 비교는 표로, 순서는 번호로 그린다. 흐름은 GSAP 모션으로 보여 주고 정적 상자 나열로 끝내지 않는다.

- 모션은 흐름을 보여 주는 장에만 쓰고 한 장에 타임라인 하나다. 장마다 반복되는 입장 애니메이션은 넣지 않는다.
- 흐름도는 HTML 상자와 inline SVG 선으로 그리고 `→` 글리프를 쓰지 않는다. 상자가 5개를 넘으면 장을 나눈다.
- 에이전트가 일하는 흐름에서 사람은 준비·명령 한 번·merge에만 그린다. 그 사이에 사람이 여러 번 끼어드는 그림으로 그리지 않는다.

## 화면은 목업으로

앱·터미널·채팅·도구 창은 HTML/CSS 목업으로 그린다. 가상 데이터를 쓰고 실제 계정명·개인 정보를 넣지 않는다.

- 무언가를 만드는 덱은 끝에서 완성된 결과의 클릭 흐름과 완료 기준을 목업으로 보인다.
- 생성형 이미지로 UI·터미널·채팅 화면처럼 보이는 그림을 만들지 않는다.
- 실제 캡처는 `deck/assets/sNN-<desc>-v01.png`로 둔다. 캡처가 오기 전에는 화면 설명 카드를 두고 "대기" 같은 준비 중 문구를 쓰지 않는다.

## 원문은 패널로

긴 원문은 장표 위 패널로 연다. 장표는 패널을 열지 않아도 이해된다.

- 패널 목록은 `deck/outline.md`의 패널 열 한 곳에만 둔다. 이스터에그는 그 열에 `(이스터에그)`로 표시하고 따로 목록 파일을 만들지 않는다.
- 이스터에그는 주제와 이어지고 장당 1개까지다. 트리거가 방향키·스페이스·`E`와 겹치지 않는다. 강사가 못 찾으면 없는 것과 같다.
- Q&A 패널은 장당 1개까지다.

## 근거는 링크로

- 외부 저장소·서비스 이름은 원본으로 가는 링크로 건다.
- 도구 로고는 공식 출처의 파일만 쓰고 `deck/assets/logos/sources.json`에 기록한다. 기록 없는 로고는 장표에 올리지 않는다. 수집은 `deck-assets` 스킬이 한다.
- 참고 이미지의 발표자 얼굴·브랜드·가격·기술 주장을 검증된 내용으로 가져오지 않는다.

## frontend-slides 기본값 덮어쓰기

이 형식의 덱에서 `frontend-slides` 스킬을 함께 불러도 아래 표가 이긴다.

| frontend-slides 기본값 | 이 덱 |
|---|---|
| 단일 인라인 HTML, 빌드 없음 | `shell.html`·`sections/*.html`·`motions/*.js`·vendor GSAP를 빌드로 조립하고 폴더째 배포한다 |
| Google Fonts·Fontshare 글꼴 | 직접 호스팅한 IBM Plex Sans KR 400·600 |
| 스타일 시안 3개를 먼저 만든다 | 셸이 고정이고 스타일을 묻지 않는다 |
| 모든 장에 staggered reveal | 흐름을 보이는 장에만 GSAP `data-motion` |
| 테마·글꼴·그라데이션을 바꿔 가며 쓴다 | 셸 토큰 한 벌, 장식 그라데이션 없음 |
| 밀도·분량을 묻는다 | 묻지 않는다. 원고가 정하고 항목 수는 `deck-copy.md`를 따른다 |
| 장당 항목 4–6개 | `deck-copy.md`의 3~5개 |
| 1280×720과 휴대폰 화면 확인 | 1920×1080에서만 확인한다 |
| 배포 파일에 편집기 포함 | 편집은 dev 서버에서만 켜고 배포본에는 넣지 않는다 |

그대로 지키는 것은 고정 스테이지, `.active`/`.visible` 전환(`display: none` 금지), `prefers-reduced-motion` 대응, 넘치면 장을 쪼갠다는 원칙이다.
