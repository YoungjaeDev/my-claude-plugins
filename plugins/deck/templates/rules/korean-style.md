# 한국어 문체 규칙

> 원본은 `deck` 플러그인의 `templates/rules/korean-style.md`다. 이 사본을 직접 고치지 말고 원본을 고친 뒤 `deck-sync`로 다시 받는다.

한글을 쓰는 모든 파일에 적용한다. 윤문으로 걷어내는 것보다 처음부터 안 쓰는 게 싸다.

AI가 쓴 한글은 대개 한 뿌리에서 티가 난다. 영어 문장을 한국어 형태소로 갈아 끼우면 그렇게 된다.
그래서 아래는 표현 목록이 아니라 판정이다. 목록에 없는 표현도 판정에 걸린다.
예시는 자주 나오는 것을 든 것이지 그것만 막는다는 뜻이 아니다.

## 1. 영어 기능어를 형태소로 갈아 끼웠다

**판정 — 그 구절을 지우고 조사 하나로 붙여도 뜻이 같은가. 같으면 갈아 끼운 것이다.**

- `~에 대해(서)` (about) → 목적격으로 직결. "X에 대해 알아봅니다" → "X를 봅니다"
- `~를 통해`, `~를 통하여` (through) → `~로`, `~해서`, `~함으로써`
- `~에 있어(서)` (in) → `~에서`, `~을 볼 때`
- `~와 관련하여`, `~와 관련된` (related to) → `~에`, `~의`
- `~에 기반하여`, `~을 바탕으로` (based on) → `~로`, `~을 보고`
- `~을 위해` (for) 목적절 남발 → `~려고`, `~도록`
- `~에서의`, `~으로의`, `~에의` 이중 조사 → 절로 풀어쓴다
- 관형구를 셋 넘게 겹친 긴 좌향 수식 → 관계절 직역이다. 문장을 끊는다

## 2. 행위자를 지웠다

**판정 — 누가 했는지 문장에 있나. 없으면 되살린다.**

- `~에 의해` 피동 → 행위자를 주어로. "AI에 의해 생성된" → "AI가 만든"
- `~되어진다`, `~지게 된다` 이중 피동 → 능동 또는 단일 피동
- `~되고 있다`, `~지고 있다` 피동 진행 남발 → 능동으로
- `~을 가지고 있다` (have 직역) → "경쟁력을 가지고 있다"가 아니라 "경쟁력이 강하다"
- 추상 주어 + 만능 동사(`보여준다`, `제공한다`, `가져온다`) → 구체 주어로 환원

## 3. 뜻 없는 자리를 채웠다

**판정 — 그 문장을 지우면 정보가 줄어드나. 안 줄면 지운다.**

- `결론적으로`, `이를 통해`, `요약하면`, `정리하자면` — 결산 상투구
- `시사하는 바가 크다`, `주목할 만하다`, `매우 중요하다` — 의의 과장
- `크게 세 가지로 나눌 수 있다`, `다음과 같은` — 열거 도입구. 지우고 바로 본론
- `혁신적`, `획기적`, `압도적`, `전례 없는`, `폭발적` — hype 어휘
- `단순한 X를 넘어 Y로`, `X에서 Y로` — 변환 공식. 문서 전체에서 1회 이하
- `~할 때입니다`, `~시점입니다`, `~할 순간입니다` — 결말 공식. 1회 이하
- `필요한 것은 ~이다`, `핵심은 ~이다`, `관건은 ~다`, `문제는 ~다` — 분열문. 주어와 서술어를 직결한다
- `~하는 이유다` 도치 결산 → `그래서 ~다`
- `~라는 점에서`, `주목할 점은` — 형식명사 강조 → 직설로

## 4. 영어 서식을 한글에 얹었다

**판정 — 한국어 글에서 원래 그렇게 쓰나.**

- 연결어미(`-고`, `-며`, `-지만`, `-면서`, `-어서`) 직후 쉼표 → 쉼표를 뺀다. **가장 강한 AI 신호**
- 한글 + 괄호 영어 병기 반복 → 첫 등장에만. 이후 한글만
- 이모지 → 어디에도 넣지 않는다
- 문두 접속사(`또한`, `따라서`, `즉`, `나아가`, `게다가`)가 한 문단에 3회 이상 → 절반을 덜어낸다
- 대시(—) 부가 설명이 문장마다 반복 → 쉼표·괄호·별도 문장으로 분해
- 따옴표 강조 5회 이상 → 진짜 인용만 남긴다

## 손대지 않는 것

고유명사·제품명(Claude Code, Cowork, MCP), 수치·날짜, 직접 인용,
업계 표준 영어 약어(API, MCP, LLM, prompt, token, agent).
`prompt`를 "지시문"으로 옮기는 식의 기계적 직역은 하지 않는다.
내부 문서(아웃라인·CLAUDE.md)의 작업용 별칭은 예외다.
