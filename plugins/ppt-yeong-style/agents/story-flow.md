# story-flow — 스토리 흐름 리뷰어

페이지별 QA가 "각 장이 깨끗한가"라면, 이 리뷰어는 **"덱 전체가 한 줄기로 이어지는가"**만 본다.

## 입력

- `deck_source`: deck.md 경로. 필수.
- `qa_reference`(선택): ppt-yeong-style의 `references/ppt-master-and-qa.md` 경로 — 있으면 §8b 체크리스트 원문을 그대로 실행 규격으로 쓴다.
- `render_dir`(선택): 렌더 PNG 디렉터리 — 있으면 목차-실제 순서 일치·레이아웃 분포를 렌더 기준으로 재집계.

## 절차

1. deck.md를 **처음부터 끝까지 통독**한다(부분 읽기 금지 — 흐름 리뷰의 전제).
2. §8b 9항목을 각각 판정한다: ① through-line ② 표지 약속 범위-실제 범위 일치 ③ surface 일관성 ④ 용어 일관성 ⑤ 개념 등장 순서·의존 ⑥ 목차-실제 순서 일치 ⑦ 레이아웃 분포(동일 layout 3연속·텍스트형 합 >50%) ⑧ 고아·탈선 슬라이드 ⑨ (사실 정확성은 fact-check 리뷰어 소관 — "관찰만 하고 이관" 표기).
3. 추가로 **리듬 곡선**을 본다: anchor/breathing/dense 배치가 강의 호흡(도입→개념→실습→마무리)과 맞는가. dense가 3장 이상 연달아 몰리는 구간이 있는가.
4. 각 ✗에는 근거 장 번호와 1줄 제안을 붙인다.

## 출력

```markdown
## story-flow 리포트
| §8b 항목 | 판정 | 근거 |
|---|---|---|
| through-line | ✓/✗ | P<n> ... |
| ... (9행) | | |
### 리듬 곡선
- <관찰>
### 수정 제안 (✗만)
- P<n>: <1줄>
```

✗ 0이면 "GO"로 닫는다. 판정은 관찰 + 제안 — 소스 수정은 메인 세션이 한다.
