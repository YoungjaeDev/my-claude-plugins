# lecture-deck — 강의 덱 전용 운영 규약

**전제**: 이 스킬은 `ppt-yeong-style`(작성 규약)과 `ppt-master`(빌드 엔진) 위에서 동작한다. 미감·md 규약·원칙 16종·파이프라인은 메인 스킬이 SOT — 여기는 **강의 덱에만 있는 운영 문제**(실습 자료, 스크린샷 슬롯, 장 삽입, 강의 후 회고)를 다룬다. ppt-master 미설치면 메인 스킬 규칙대로 빌드 진입 전 중단.

## §1. 구성 — 강의 시간 → 덱 구조

- 장수 매핑(참고치, 인터뷰 우선): 30분=15~18 / 60분=25~30 / 90분=35~42 / **3시간=45~50**(휴식 2회 전제).
- 3시간급 표준 골격: 표지·목차 + 부 5~6개(부마다 pop divider 1장) + 실습 3~4개(부와 교차 배치 — 개념 2~3장마다 손 움직일 거리) + 마무리(다음 스텝 1개 구체 행동) + 용어 참조표.
- 실습 장은 **checklist 리듬 + 실습 배지**(번호 pill)로 통일해 "여기서 손 움직인다"가 스캔만으로 보이게.
- 수정 규율(공통): 모든 장 수정은 ① `sources/deck.md`(내용 SOT) → ② `spec_lock.md` 계약 확인 후 해당 장 SVG → ③ `notes/` 동기 → ④ 장별 렌더 QA. **deck.md 안 고치고 SVG만 고치는 우회 금지.**

## §2. 실습 handouts 생성 규약

실습 자료는 "그럴듯한 파일"이 아니라 **실습 지시문과 정확히 맞물리는 파일**이어야 한다.

- **추출 실습**(예: 회의메모→요약): 뽑아야 할 정보(결정·담당·기한)가 자료에 실제로 명확하게 들어있게 만든다. 동시에 **노이즈도 심는다** — 논외 잡담·보류 안건을 섞어야 "AI가 핵심만 골랐다"가 체감된다. 전부 신호뿐인 자료는 실습 난이도가 0이 된다.
- **교정 실습**(예: 공지 문체 통일): 의도된 결함(문체 불일치·오탈자·서식 편차)을 실제로 심는다. 결함 유형을 다양화(높임 혼용·맞춤법·날짜 표기·구어체)해 규칙 여러 줄이 각각 일할 거리를 갖게.
- **생성 실습**(예: 명단→안내문): 입력 데이터에 결과물 차별화 축(부서·직급 열)을 넣어 "규칙대로 나눠 그려졌다"가 눈에 보이게.
- 자연스러운 한국어 실물처럼 — placeholder 티(홍길동·Lorem·"예시입니다") 금지. 인명·부서·일정은 서로 교차 참조되게(회의 참석자가 roster에 존재).
- **생성 후 대조 검증(MANDATORY)**: 실습 지시문의 각 스텝을 자료에 대고 실제로 수행 가능한지 1회 시뮬레이션. "결정·담당·기한만 뽑아" 지시인데 기한 없는 결정이 자료에 있으면 자료를 고친다.

### 실습 프롬프트 카드 (`handouts/exercise_prompts.md`)

강의 중 "프롬프트를 안 드렸네요"가 나오면 실습이 5분 지연된다(실측). 덱과 별개로 **복붙 카드 1파일**을 항상 동봉한다:

- 실습별: 준비 1줄 + **시작 프롬프트**(코드블록, 그대로 복붙 가능) + 후속 프롬프트 1~2개 + **예상 화면 한 줄**("승인 화면이 뜹니다" 등 — 낯선 화면 예고).
- 프롬프트 문구는 덱 실습 장의 체크리스트와 토큰 단위로 일치시킨다(카드 따로 덱 따로 금지).

## §3. 스크린샷 슬롯 운영 — placeholder가 빌드를 막지 않게

앱 UI는 실물 스크린샷만(AI 생성 금지 — 메인 스킬 §3c) 유지하되, 캡처 미보유로 덱 출고가 막히면 안 된다.

1. **슬롯 선언**: 미보유 UI는 점선 박스(`stroke-dasharray`) + 설명 + "캡처 후 교체" 라벨로 렌더. `S_<이름>` 명명으로 spec_lock `images` 절 + deck.md `image-slot` 주석에 placeholder임을 명시. 이 상태로 export까지 완주 가능.
2. **수령 안내는 스킬이 먼저**: 사용자에게 "어느 화면을 어떤 상태로 캡처해 `images/`에 어떤 파일명으로" 넣을지 슬롯 목록으로 안내한다(수동 대기 금지).
3. **실측 비율 프레임(shrink-to-hug)**: 캡처 수령 시 프레임을 먼저 그리고 이미지를 욱여넣지 말 것 — PIL 등으로 실측 → 필요 시 `_crop` 파생 생성 → 프레임을 이미지 비율에 맞춰 재계산.
4. **교체 + 3중 등재 해소**: 해당 장 점선 박스 → `<image>` 교체, spec_lock images(placeholder 줄→user row)·deck.md 주석·design_spec §VIII를 같은 커밋에서 동기화. 남은 placeholder 카운트 grep 0 확인.
5. **문구 정합 재검(실측 교훈)**: placeholder 시절 상상으로 쓴 설명 문구는 실물과 어긋날 수 있다 — 캡처가 들어오면 그 장의 키 메시지·카드 문구를 실캡처 기준으로 재검한다(실측: "바뀐 줄만 보여줌" → 실캡처는 쓰기 승인 프롬프트라 "무엇을 어디에 쓸지 먼저 물어봄"으로 정정).

## §4. 리넘버링 파이프라인 — 장 삽입/삭제 시

삽입 지점이 N곳이어도 **read-all-then-write-all**: 새 번호 매핑을 전부 계산한 뒤 일괄 기록(순차 rename은 P11→P12가 기존 P12를 덮는 충돌).

- **보호 패턴 구분**: 부 divider의 hero_number(부 번호 "03")와 header의 페이지 번호("14")는 둘 다 큰 숫자 텍스트다 — 좌표/스타일 패턴으로 구분해 페이지 번호만 갱신(부 번호를 밀면 divider가 "04부"가 된다).
- **4중 동기화**: `svg_output/P*.svg` 파일명·내부 페이지번호 + `notes/P*.md` 파일명 + `sources/deck.md` 순서 + `spec_lock.md` page_rhythm(+ `design_spec.md` 로스터). 목차(TOC) 장과 부 구성 문구도 재확인.
- 리넘버링 후 **quality check 전수** + 대괄호 grep 0 재확인.

## §5. 표 행 수 변경 시 재배치

행 추가/삭제는 한 행을 끼워넣는 게 아니라 **표 전체 재계산**이다: 행 높이·구분선 y좌표·헤더 밴드·표 바깥 하단 요소(팁 칩·footer 룰·각주)까지 연쇄 이동. 본문 바닥 20pt를 깨지 않는 행 높이를 먼저 정하고(6행이면 40px대) 전체를 다시 그린다. 기존 간격에 한 행만 밀어 넣으면 밴드 정렬이 깨진다(design-qa 적발 대상).

## §6. 전사 회고 루프 — 강의 후 덱 개정

강의 덱은 출고가 끝이 아니다. 실강의 전사가 다음 개정의 1차 증거다.

1. **전사 확보**: 강의·실습 세션 녹취 전사(Summary+transcript 쌍이면 둘 다).
2. **fork 분석**: 1시간+ 전사는 fork/서브에이전트에 정독을 위임(메인 컨텍스트 보호). 세션당 1개.
3. **커버리지 맵**: 산출물은 "현장 사건 ↔ 덱 장" 매핑 5분류 — ① 덱 적중(기존 장이 질문을 받아냄) ② 미커버 질문(보강 후보) ③ 덱-현장 충돌(정정 필수) ④ 미수록 실전 지식(강사 즉흥 답변) ⑤ handout 공백.
4. **보강 원칙**: 신규 장 추가보다 **기존 장 보강 우선**(장수 불변 기본). 과정 범위 밖 질문은 별도 과정 백로그로 이관 — 본 덱을 부풀리지 않는다.
5. **운영 실수는 notes로**: 내용 공백과 별개로, 전사에서 드러난 강의 운영 실수(시연 생략·수치 혼용·즉흥 답변)는 §7 강사 노트 태그로 박는다.

## §7. 강사 노트 운영 규약 (`notes/P*.md`)

노트는 대본 요약이 아니라 **운영 지시서**다. 전사 회고에서 검증된 태그 어휘:

- **[시연 필수]** — "가장 중요하다"고 선언하는 장은 선언에 비례하는 시연 시간을 배정(중요도 선언 ∝ 시연 시간). 노트 첫머리에 태그 + 1회 실연 대본(스텝 나열)을 박는다.
- **[수치 고정 대본]** — 컨텍스트 크기 같은 수치는 덱에 박힌 문장 그대로만 발화. 같은 수치 계열을 다루는 장이 여럿이면 장별 분담을 노트에 명시(예: 정의 장=모델·1M까지만, 운영 장=60% 기준).
- **[표를 그대로 읽어라]** — 보안·데이터 등 신뢰 민감 장은 즉흥 답변 대신 덱의 검증 팩트 낭독.
- **[주차장 멘트]** — 과정 범위 밖 질문(배포·개발 등)의 정중한 이관 멘트를 미리 준비("그건 중급 과정에서 + 끝나고 개별로").
- **[라인업 재확인]** — 모델명·요금 등 시점 종속 정보 장은 "강의 전 실화면 대조" 메모.
- **선제 팁** — 현장에서 반복 소모되는 막힘(숨김폴더 안 보임 등)은 해당 장 노트에 OS별 해법을 미리("Mac Cmd+Shift+. / Win 보기>숨긴 항목").
- 어투: 덱에 출처 있는 사실은 단정형으로 — "~인 것 같습니다" 추정 어투는 정말 불확실한 것에만.

## §8. 레퍼런스 — 완성 덱 실례

47장·3시간 강의 덱의 완성 실례(로스터·리듬 배분·검증 게이트 이력·대표 렌더 5장)는 → `references/cc-common-reference.md`. 새 강의 덱의 구조 설계 시 출발점으로 삼되, 장수·부 구성은 인터뷰가 우선.

## 의존

- `ppt-yeong-style`(작성 규약)·`ppt-master`(엔진, prerequisite — 미설치 시 빌드 진입 전 중단)는 전제.
- `interview`·`anti-slop-design`·`humanize-korean`·`codex-image`·`design-shotgun`·`codex:rescue`: 있으면 해당 단계에서 사용, **없으면 생략 + 설치 제안 문구 출력**(메인 스킬 §0b와 동일 패턴).
- 리뷰는 `deck-review` 스킬(동봉)로 — 4관점 에이전트 + codex 교차 리뷰.
