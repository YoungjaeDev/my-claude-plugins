# ppt-yeong-style 빌드 완료 게이트 강화 설계 (스토리 구조 · 품질 게이트 · 이미지 기본값)

- 작성일: 2026-07-02
- 상태: draft (승인 대기, 1차 리뷰 피드백으로 스코프 확장)
- 관련 스킬: `plugins/ppt-yeong-style/skills/ppt-yeong-style/`
- 근거: 다른 repo(woogang-chatbot)에서 ppt-yeong-style + anti-slop-design으로 포트폴리오 덱을 만든 세션 전체를 리뷰, 설치된 `ppt-master` 플러그인(`~/.claude/plugins/marketplaces/ppt-master/skills/ppt-master/`) 파일트리로 직접 검증

## 1. 배경과 목적

woogang-chatbot 세션 리뷰에서 두 개의 구체적 버그가 나왔다: (a) 목차(TOC) 슬라이드가 나열한 순서와 실제 빌드된 페이지 순서가 달랐다, (b) 표지가 약속한 범위("검색·평가·배포까지")보다 실제 빌드 범위(배포 섹션 제외)가 좁았다. 두 버그 다 `ppt-master-and-qa.md` §8b "스토리 흐름 review"가 "through-line"·"개념 등장 순서"라는 이름으로 이미 다루고 있었고, 그 규칙은 `SKILL.md` 파이프라인 줄·§8b 본문·`injection-prompt.md` "[완료 기준]" 줄까지 최소 세 곳에 이미 명시돼 있었다. 그런데도 두 번의 빌드 시도(폐기된 것·수정된 것) 모두 사용자가 "스토리 흐름 어때?"라고 먼저 묻기 전까지 이 리뷰 자체가 실행되지 않았다.

별개로, ppt-master의 실제 `references/modes/_index.md` §2 auto-selection표를 직접 읽어 확인한 결과 "Strategic decision / analysis / board / investor → `pyramid`" 신호가 있고, `pyramid` 모드에는 SCQA(Situation-Complication-Question-Answer) 오프닝 스켈레톤이 내장돼 있다(`modes/pyramid.md`로 직접 확인). woogang 콘텐츠("4개 검색 전략 비교 후 1개 확정")는 정확히 이 신호에 해당하는데, `ppt-master-craft.md`의 mode 레버 행은 지금 "제안 덱 → narrative/pyramid 중 인터뷰 판단"이라고만 돼 있어 이 구체적 트리거를 주지 않는다. `pyramid`를 제대로 골랐다면 페이지 순서가 SCQA 스켈레톤을 따라 애초에 안정됐을 것이고, 목차 불일치 버그 자체가 덜 생겼을 것이다.

**1차 리뷰 피드백으로 스코프 확장.** 사용자가 스펙 초안을 보고 "§8b만 고치는 건 너무 좁다"고 지적했다 — 실제로 트랜스크립트를 다시 보면 §1 파이프라인의 **(6) 품질 게이트 3종**(anti-slop-design audit → humanize-korean 윤문 → §8b 스토리 흐름 review) 전부가 같은 방식으로 스킵됐다: `anti-slop-design` 스킬은 빌드 *전* 규칙 확인용으로 한 번 로드됐을 뿐, 빌드 *후* 실제 감사 실행 흔적이 트랜스크립트에 없고, `humanize-korean` 윤문 실행 흔적도 없다. 즉 §8b는 세 개 중 하나였을 뿐 — "규칙이 문서에 있어도 빌드 완료를 서두르면 통째로 스킵된다"는 게 진짜 패턴이다. 별도로, 8대 확인 h(이미지)에서 코드가 "표지·구분선만 기존 재사용 텍스처, 나머지 4장은 이미지 없음"이라고 답했는데 — `images-and-pop.md` §5는 "이미지: 기본 codex-image"라고 명시하고 있어, 이건 품질 게이트 스킵이 아니라 **기본 레버 자체를 사유 없이 이탈**한 별개의 문제다.

목표: 문제를 사후(빌드 후 리뷰)에만 잡는 구조에서, **원인 단계(mode 선택·목차 작성 시점)에서 줄이고 + 사후 품질 게이트 3종(anti-slop 감사·윤문·스토리 흐름)을 한데 묶어 스킵 못 하게 강제 + 이미지 기본값 이탈에 사유를 명시**하게 하는 쪽으로 옮긴다.

## 2. 검토한 대안과 선택

### 2.1 mode 트리거 (craft.md)

| 접근 | 내용 | 채택/기각 사유 |
|---|---|---|
| **A. 기존 mode 레버 행에 트리거 한 줄 추가 (채택)** | "비교→확정 구조면 pyramid 우선(SCQA·MECE 내장)"을 기존 표 셀에 추가 | PR #87이 같은 표에 mode/visual_style 행을 추가한 방식과 결이 같음. 새 섹션 없이 최소 변경 |
| B. 별도 "mode 선택 콘텐츠 신호" 소제목 신설 | ppt-master의 auto-selection표 구조를 통째로 미러링 | 테이블 하나 더 늘어나는 유지보수 비용 대비 이득 작음 — 기각 |

### 2.2 품질 게이트 3종 통합 (qa.md + SKILL.md) — §8b에서 확장

| 접근 | 내용 | 채택/기각 사유 |
|---|---|---|
| A. §8b만 리스트에 항목 2개 추가 | "목차-실순서 일치"·"표지약속-범위 일치"를 §8b에만 이름 붙은 불릿으로 추가 | 1차 리뷰에서 기각 — anti-slop 감사·윤문도 같은 방식으로 스킵됐는데 §8b만 고치면 나머지 둘은 그대로 재발함 |
| **B. 품질 게이트 3종(anti-slop 감사·윤문·§8b 스토리 흐름)을 하나의 "완료 게이트 리포트"로 통합 + TOC 최종 작성 시점 규칙 (채택)** | §2에 "TOC는 페이지 순서 확정 후 마지막에 작성" 규칙 추가(원인) + qa.md에 새 "§8c 완료 게이트 리포트" 신설, 빌드 완료 보고 전 anti-slop 감사 결과·윤문 적용 여부·§8b 체크리스트(목차·표지범위 항목 이름 붙여 포함)를 **하나의 리포트로 실제 출력**해야 완료 선언 가능(안전망) | 세 게이트가 같은 파이프라인 줄·같은 실패 패턴을 공유하므로 하나의 메커니즘으로 묶는 게 유지보수·재발방지 양쪽에 유리 |

### 2.3 codex-image 기본값 이탈 사유 명시 (images-and-pop.md)

별도 대안 비교는 불필요 — `images-and-pop.md` §5가 이미 "이미지: 기본 codex-image"를 명문화하고 있으므로, 그 기본값을 벗어날 때(이미지 없음·기존 자산 재사용) **design_spec.md 8대 확인 h에 한 줄 사유를 남기게** 하는 작은 규칙만 추가한다. 사유 없는 이탈은 허용하지 않는다.

## 3. 변경 파일 및 내용

### 3.1 `references/ppt-master-craft.md` (mode 레버 행)

기존 "제안 덱 → `narrative`/`pyramid` 중 인터뷰에서 판단" 뒤에 괄호로 트리거 추가:

> (콘텐츠가 **여러 옵션을 비교해 1개로 확정**하는 구조면 `pyramid` 우선 — SCQA 오프닝[Situation→Complication→Question→Answer]과 MECE 비교가 내장돼 있어 페이지 순서·비교 논리가 저절로 안정된다. ppt-master 자체 auto-selection표의 "Strategic decision/analysis/board/investor → pyramid"와 일치. 스토리가 서사 아치[기승전결]로 가는 제안이면 여전히 `narrative`.)

### 3.2 `SKILL.md` §2 md 소스 작성 규약 (TOC 작성 시점)

목차 슬라이드 작성 규칙 한 줄 추가: 목차(TOC)는 다른 슬라이드와 같이 초안 단계에서 쓰지 않는다 — **전체 페이지 순서가 spec_lock에 확정된 뒤 마지막에** 그 순서를 그대로 옮겨 적는다. 순서가 나중에 바뀌면 목차도 같이 갱신(재확인 없이 방치 금지).

### 3.3 `references/ppt-master-and-qa.md` §8b→§8c (품질 게이트 3종 통합 리포트)

- §8b는 그대로 두되(through-line·surface 일관·용어 일관·개념 등장 순서·고아 슬라이드·사실 정확), 두 항목을 이름 붙여 분리: **"목차-실제 순서 일치"**(개념 등장 순서에서 분리) / **"표지 약속 범위-실제 빌드 범위 일치"**(through-line에서 분리) — 재발한 두 버그가 각각 이 이름으로 걸리게.
- 새 **§8c. 완료 게이트 리포트 (통합, MANDATORY)** 신설: 빌드 완료를 사용자에게 보고하기 전 아래 3개를 **실제로 실행하고 그 결과를 하나의 리포트로 출력**해야 완료 선언이 가능하다(내부적으로 판단만 하고 넘어가는 것 금지):
  1. **anti-slop-design audit** — 설치돼 있으면 그 스킬의 감사를 실행한 결과(적발 항목 수·수정 여부), 없으면 §3 원칙 15종 체크리스트로 수동 대체한 결과.
  2. **humanize-korean 윤문** — 적용 여부와 적용 범위(fast/strict), 미설치 시 §7 차단 목록 수동 체크 결과.
  3. **§8b 스토리 흐름 체크리스트** — 항목별 ✓/✗(신설된 "목차-실순서"·"표지약속-범위" 포함).
  - 셋 중 하나라도 "미실행"이거나 ✗가 있으면 완료 보고 대신 해당 장 수정 또는 감사/윤문 재실행부터.
- SKILL.md §1 파이프라인 줄의 "anti-slop-design audit → humanize-korean 윤문 → 렌더 Visual QA + 스토리 흐름 review" 문구도 "→ **완료 게이트 리포트**(anti-slop 감사·윤문·스토리 흐름 통합 출력)"로 갱신해 이 강제가 파이프라인 개요에서부터 보이게 한다.

### 3.4 `references/images-and-pop.md` §5 (codex-image 기본값 이탈 사유)

§5 "기본 이미지 경로" 서술 뒤에 규칙 추가: 이미지 없음(SVG 전용)이나 기존 자산 재사용으로 갈 경우, design_spec.md 8대 확인 항목 h에 **왜 기본 codex-image 경로를 타지 않는지 한 줄 사유**를 명시한다(예: "이 장은 표·숫자 정확도가 핵심이라 이미지 불필요", "이전 세션에서 이미 승인된 텍스처 재사용"). 사유 없이 그냥 생략하는 것은 금지 — §5b(사용자 제공 스크린샷)처럼 명시적 경로가 없는 "기본 이미지도 아니고 사용자 제공도 아닌" 이탈을 잡기 위함.

## 4. 이번 라운드에서 제외 (다음 라운드 후보)

- **엔진 우회(스크립트로 SVG 직접 생성) 방지용 PreToolUse 훅** — 별도 브레인스토밍으로 진행하기로 확정(이 설계와 독립적인 메커니즘이라 별도 스펙).
- **`injection-prompt.md`의 PR #87 동기화 누락** — 이번 조사에서 발견됐지만 이번 설계(스토리 구조)와는 무관한 별개의 lever-alignment 콘텐츠 동기화 문제. 별도 소규모 후속으로 남긴다.
- SCQA를 `pyramid` 외 다른 mode에도 부분 적용하는 것 — 현재 근거(ppt-master 자체 문서)가 `pyramid` 모드에만 SCQA를 명시하므로 확장하지 않는다.
- **anti-slop-design 자체의 감사 로직 수정** — 그 플러그인은 별도 owner다(bare-name 참조 원칙). 이번 설계는 ppt-yeong-style 쪽에서 "그 감사가 실제로 실행됐는지"만 강제하고, 감사 내용 자체는 건드리지 않는다.

## 5. 검증 방법

문서(스킬 md) 변경이라 자동 테스트는 없다. 대신:
1. 각 파일 수정 후 `python3 -c "import yaml; yaml.safe_load(...)"` 류로 SKILL.md frontmatter 파싱 이상 없는지 확인.
2. 새 §8c(완료 게이트 리포트)가 기존 §8(Visual QA, 렌더 기반 완료 기준)·§8b(스토리 흐름)과 형식·용어가 충돌하지 않는지 대조.
3. `node scripts/sync-codex-manifests.mjs --check` / `sync-hermes-manifests.mjs --check` 통과 확인(설명 변경 없어 영향 없을 것으로 예상, 회귀 확인 차원).
4. 실사용 검증: 다음에 "여러 옵션 비교 후 확정" 구조의 덱을 만들 때 mode 트리거가 실제로 pyramid 선택을 유도하는지, §8c 완료 게이트 리포트가 실제로 출력되는지, 이미지 없음/재사용 선택 시 사유가 design_spec에 남는지로 확인 — 사용 시점 검증이라 이번 PR에서 자동 확인은 안 됨.
