# 이미지 — codex-image vs SVG, fade·pop, 스크린샷 (§5 + §5b)

경계가 핵심이다 — 셋으로 나눈다: **서사·무드는 codex-image, 정확한 라벨·표·정형 차트는 ppt-master SVG, 자유형 구조 도식(관계·플로우·트리)은 drawio PNG.** **장식** pop/단순 마스코트 아이콘은 표지·전환에만 — 단 서사 신호를 지닌 개념 메타포 일러스트는 본문에도 opt-in(§5d).

## §5. codex-image vs ppt-master SVG

- **codex-image**(기본 이미지 경로, ppt-master 밖 별도 도구): 사진·무드컷·배경(흐림/바램)·전략적 hero·표보다 이미지가 나은 도식. 한/영 레터링 품질 양호 — **생성 성능을 매번 반문하지 말 것**(saturation). 톤 통일을 명시(디자인 토큰 hex + 캐릭터 참조 이미지 첨부)하고, 생성 후 라벨 오타를 검증. ppt-master의 AI 이미지 생성 경로(Step 5 ai)는 **기본 사용 안 함** — 이미지는 codex-image로 채운다.
- **ppt-master SVG**: 정확한 한국어 라벨·구조·표·숫자·타임라인. 텍스트 정확·수정 가능.
- **하이브리드**: 무드 배경(codex) + 라벨 오버레이(SVG). 도식 2안(풀 codex vs 하이브리드)을 렌더 후 사용자 선택.
- **기본값(codex-image) 이탈 시 사유 명시**: 이미지 없음(SVG 전용)이나 기존 자산 재사용으로 갈 경우, `design_spec.md` 8대 확인 항목 h에 **왜 기본 codex-image 경로를 타지 않는지 한 줄 사유**를 남긴다(예: "이 장은 표·숫자 정확도가 핵심이라 이미지 불필요", "이전 세션에서 이미 승인된 텍스처 재사용"). 사유 없이 그냥 생략하는 것은 금지.

> codex-image 미설치 시: 무드 배경은 생략하거나 단색/그라데이션 SVG 배경으로 degrade. 라벨·표는 그대로 SVG.

## 도구 삼분 — codex / SVG / drawio

현재 SVG 버킷이 "정확 라벨·표"와 "구조 도식"을 둘 다 갖고 있어 경계가 흐리다 → 셋으로 가른다:

| 도구 | 담당 | 예 |
|---|---|---|
| **codex-image** | 스토리 메타포 일러스트(서사·장면·감성), 무드컷·배경·hero | 배터리 하루, 분신 회의실, 표지 배경 |
| **ppt-master SVG** | 정확 라벨·표 + **정형** 차트(`charts_index.json`: 타임라인·매트릭스·피라미드) | 명령어 표, 대괄호 키메시지, 일정 타임라인 |
| **drawio PNG** | **자유형** 구조 도식(임의 박스+화살표 관계·플로우·트리·아키텍처) | 하네스 구조도, 파일 트리, 서브에이전트 관계도 |

판정: 정형 표/차트=SVG, ppt-master 템플릿에 없는 자유형 관계·플로우=drawio, 서사=codex. drawio가 ppt-master 자체 diagram 경로를 이기는 건 **자유형·복잡 관계일 때만** — 정형은 SVG 우선. (drawio는 `drawio:drawio-skill`로 PNG export — SKILL.md §0b 의존 스킬, 있으면 사용·없으면 생략.)

## codex 레터링 경계 + 폰트 옵션

- **레터링 최대 활용 + SVG 폴백**: codex 한글 레터링은 짧은 라벨·말풍선에 **적극 활용**한다 — 이 길이는 자소분리·오타 없이 정확하다(실측: 3패널 라벨·말풍선 전부 정확히 렌더). 다만 다음은 **SVG로 폴백**한다: ① 자주 바뀌는 문구(전사 회고로 수정 잦음 — 이미지에 박으면 수정 때마다 재생성해야 하고 캐릭터·구도가 달라진다) ② 정확 수치·명령어 ③ **대괄호 키메시지**(SKILL.md §2 bracket-strip이 SVG 경로) ④ 폰트를 덱 전체(Pretendard)로 통일해야 할 때. 폴백 근거는 "codex가 한글을 못해서"가 **아니라** "수정 가능성·폰트 통일·키메시지 규약"이다.
- **폰트 스타일 옵션**(codex 레터링 글꼴 — 프롬프트로 지정, default는 **그림 스타일에 종속**):

  | 옵션 | 프롬프트 키워드 | 어울리는 스타일 |
  |---|---|---|
  | 깔끔한 산세리프 | `clean sans-serif label` | 플랫 explainer (default) |
  | 손글씨·마커 | `handwriting / marker lettering` | 코믹·화이트보드 (default) |
  | 둥근 고딕 | `rounded friendly lettering` | 친근·부드러운 톤 |

  지정 없으면 그림 스타일별 default(플랫→산세리프, 코믹→손글씨)를 쓰고, 언제든 프롬프트로 교체한다. (덱 텍스트 렌더 폰트 폴백 체인은 별개 축 → `color-typography.md`.)

## codex 실측 교훈 (프롬프트 문구)

- **"flat, no gradient" 과잉 강조 금지** — codex가 이를 과잉 해석해 팔레트를 강제로 뭉갠다(실측: 866KB→23KB로 폭삭, 엣지 깨짐). **`flat vector with soft subtle shading`**으로 완화하면 정상이다. 이건 *codex 프롬프트 문구* 레이어 교훈이지, 덱 output의 그라데이션 금지(`design-language.md`)와 다른 층이다 — 덱 렌더엔 여전히 그라데이션 텍스트·다색 금지.
- **역할색은 프롬프트에 명시** — 안 하면 codex가 관습색을 쓴다(실측: 배터리를 신호등색 초록→노랑→빨강으로 그림 → 우리 역할색과 충돌). "battery charge in orange, not green"처럼 역할색을 못박는다.

## codex 배경 fade 범위

- **표지·섹션 전환 divider·마무리 한정.** 텍스트 가독성 위해 **opacity 0.12~0.16**으로 옅게 바램(저채도·흰 오버레이).
- **본문 슬라이드 배경은 흰색 유지**(배경 미적용, 부득이하면 ≤0.16 극히 옅게).
- 참조 풀: **브랜드/캐릭터 참조 이미지 폴더**(예: `assets/<brand>/`)를 codex-image 프롬프트에 캐릭터·톤 참조로 첨부, 디자인 토큰(예: 주황 `#D97757`·오프화이트) 준수.

## 장식 pop·마스코트 (표지·전환 — 본문 서사는 §5d)

> codex 일러스트의 **주 용도는 본문 개념 설명(§5d 스토리 일러스트)**이다. 이 섹션은 그 외 *장식* pop·마스코트 — 표지·목차·전환 divider 한정.

- **표지·목차·세션 전환 divider에 적극.** codex 생성 마스코트(브랜드 픽셀 캐릭터 참조) + 밝은 pop 무드(주황 포인트).
- 목차 = 섹션 리스트 + 마스코트. 부 전환 divider = 큰 부 제목 + 마스코트 + pop 배경.
- codex-image 호출 시 항상 `--ref <실제 참조 이미지>` 첨부(자리표시자 경로 금지). **"참조 첨부는 동작 unverified"라는 판단으로 텍스트 전용 프롬프트로 대체하지 말 것** — 이 저장소·프로젝트의 과거 codex-image 산출물(`assets/generated/codex-image/`)에 성공 선례가 있는지 먼저 확인하고, 확인 없이 unverified로 단정해 규칙을 우회하지 않는다(실측: 재확인 없이 우회했다가 캐릭터 없는 추상 이미지만 나와 재생성한 사례). `--ref`는 그 이미지를 **수정하지 않고** 새 이미지 생성의 스타일·캐릭터 참조로만 쓴다 — 기존 이미지를 고치는 `--edit`과 다른 옵션. **미검증 주의**: edit-vs-reference 구분은 `codex exec -i` 전달 자체가 아니라 프롬프트 문구에 전적으로 의존한다(codex-image SKILL.md 참조) — 이 저장소에서 실제 생성으로 검증된 적 없다. 첫 실사용 시 결과가 참조 이미지의 단순 복제·수정이 아니라 진짜 새 이미지인지 확인하고, 아니면 사용자에게 보고.

## anti-slop ↔ pop 경계 (명문화)

- **장식** pop/instagram 감성·**단순 마스코트 아이콘**은 **표지·목차·전환 divider에서만.** (서사 신호를 지닌 개념 메타포 일러스트는 본문 opt-in 예외 → §5d.)
- 본문은 **anti-slop 기본** — 그라데이션 텍스트·다색 텍스트·icon-tile 균일그리드·이모지 금지, chrome 효과 남용 금지. "pop"은 사진 fade의 무드로만 표현.
- **장르 주의**: 기업·포멀 덱은 pop/마스코트 생략 가능, 강의·캐주얼 덱에서 권장.
- **pop = 감정신호 (honesty test, 톤 버전)**: pop/마스코트/액센트 블록·버스트는 **위계 정점(표지·전환 divider·큰 숫자 1개)에만 격리**하고, 그 자리에서 **감정·내러티브 신호를 실어야** 한다(시그니처의 "one committed loud moment per page"). **톤 정보가 없으면 — 즉 빼도 의미·감정 손실이 없으면 — slop이므로 삭제.** 장식으로서의 pop은 금지. 한 장에 pop 하나(요소마다 금지). 같은 이미지 반복 금지(title/closing 로고 제외). **이 honesty test를 *통과하는* 것 — 서사·개념 신호를 지닌 스토리 일러스트 — 은 본문 장에도 허용된다(§5d).** 표지·전환 격리는 *장식* pop에만 적용되지, 서사 일러스트를 본문에서 금지하는 게 아니다.
- **사진 처리(시그니처)**: 사진은 장식이 아니라 에디토리얼 소재 — **B&W/저채도 = 권위, 통제된 컬러 = 즉시성.** 단일 액센트 오버레이·옅은 그레인, 과감한 의도적 크롭, 타입이 사진 위로 침범. glossy 스톡 톤 금지. (상위 계약 → `design-language.md` 6축.)
- 강의 PDF 등 외부 이미지는 **참고만(구조·아이디어)** → 우리 스타일로 재제작. 원문 복붙 금지.

## 스토리 개념 일러스트 (본문 opt-in) [§5d]

codex-image의 **본문 허용 범주** — 위 "pop=표지·전환만"의 예외다. **제약을 푸는 게 아니라 범주를 쪼갠다**: 장식 pop·단순 마스코트 아이콘은 표지·전환 그대로, **서사 신호를 지닌 개념 메타포 일러스트**는 honesty test(`design-language.md` §6 "톤 정보 없으면 삭제")를 *통과하는* 새 범주로 본문 장 단위 opt-in. `<!-- visual: concept-story(codex-image) -->`로 켠다. anti-slop 본문 미니멀과 충돌하지 않는다 — 미니멀이 금지하는 건 그라데이션·다색·icon-tile·이모지·chrome이지 "서사"가 아니고, 스토리 일러스트도 그 금지(flat·역할색·모티프 1개)를 그대로 지킨다(signature within trust의 본문 확장).

- **honesty test 게이트**: "개념이 벌어지는 장면·서사"여야 한다. 캐릭터가 소품 하나 든 **정적 아이콘은 reject**(실측: 마스코트가 배터리를 안고 선 이미지는 이야기가 없어 반려 — "스토리 있는 메타포"로 재작성해 통과). 원칙 11(개념=도식 우선)·§3b 일상 비유의 **시각화 대안**이지 대체가 아니다 — 장 단위로 도식 대신 선택한다.

**개념유형 → 서사패턴 매핑** (SKILL.md §2 "도식 형태 변주"가 *구조 도식*을 변주하듯, 이건 *서사 컷*을 변주한다):

| 개념 유형 | 서사 패턴 | 예 |
|---|---|---|
| 상태·속성 (쓸수록 변함) | 단일 드라마틱 씬 (스케일 대비) | 컨텍스트=거대 배터리 |
| 워크플로우·인과 (순서) | 3패널 문제→시도→해결 | 배터리 하루(아침·오후·정리) |
| 감정·심리 장벽 | 3패널 + 마지막 컷 감정 피크 | 설치공포 → "해냈다" |
| 역할·협업 | day-in-the-life (여러 분신이 하루를 나눠 일함) | 서브에이전트 |

- **마스코트 연기 — 몸은 미니멀, 상황으로 연기**: 클로드 몸(주황 둥근 사각 + 검은 사각 눈)은 그대로 두고, 스토리는 **표정(눈 크기·기울기)·몸통 기울기·소품·조연·배경·컷**으로 만든다. **"물건 든다 ✗ / 상황에 휘말린다 ✓"**(사각 몸통의 표현력 한계 우회). 조연은 표정을 단순하게(주인공을 안 뺏긴다).
- **반복 시각 모티프 1개 + 역할색 고정**: 덱을 관통하는 반복 시각 요소 1개를 정해 장면 곳곳에 심는다(GitHub Mona의 git-lines 기법 — 마스코트가 장식이 아니라 개념 세계의 능동 참여자). 색은 역할로 고정(`color-typography.md` 역할·면적 팔레트 재사용) — 주황=클로드, 오프화이트=배경, 회색=잡동사니, 갈색=선. **역할색을 프롬프트에 명시**한다(위 "codex 실측 교훈"의 신호등색 함정).
- **Corporate Memphis(=slop) 회피**: 긴 팔다리·작은 머리·다색 플랫 캐릭터(하이파이브·화분 물주기 류)가 "AI slop"의 실명이다. **unDraw·Storyset 기본 출력물이 대체로 이 스타일 — 드롭인 금지**, 구도 참고용 뼈대로만 쓰고 우리 마스코트로 재작화한다.
- **캐릭터 일관성**: 마스코트 참조 이미지를 `--ref`로 첨부(위 "마스코트·pop" 규약) + 고정 프롬프트 문구를 반복한다 — `same minimal Claude mascot, orange #D97757 rounded-square body, black square eyes, simple smile; carry identity, not pose/background`. 장면별 변주는 표정·기울기·소품만(실측: 참조 첨부 시 여러 장면에서 정체성 유지됨). 레터링·폰트·실측 교훈은 위 §5 서브섹션 참조.

## §5b. 사용자 제공 스크린샷/이미지 배치

직접 넣는 스크린샷·캡처(예: 데스크탑 앱 화면)는 **두 방식으로 약속**한다. ppt-master의 `Acquire Via: user` / `Status: Placeholder` 메커니즘에 얹는다.

1. **슬라이드 단위 지정** — 해당 장 md에 슬롯 표시:
   ```markdown
   <!-- visual: user-image -->
   <!-- image-slot: images/03_app_screen.png | 앱 설정 화면 -->
   ```
   ppt-master Strategist가 이 행을 design_spec §VIII Image Resource List에 `Acquire Via: user` / `Status: Placeholder`로 등록.

**규칙:**
- 파일 있으면 → 해당 장에 배치(safe-zone overlay·풀블리드 규칙 적용, 캡션은 SVG 텍스트로).
- 파일 없으면 → **점선 placeholder 박스 + 캡션으로 자리 유지**(슬롭 아님, 의도적 placeholder). Step 7 image readiness gate가 누락 파일명을 안내, 채운 뒤 재빌드.
- **앱 UI(로그인·diff·권한·설정·세션 등)는 실물 캡처 또는 점선 placeholder만 — codex/AI 생성 절대 금지.** 실제 화면이 진실이고 버전 종속이라, 지어낸 UI는 **틀린 UX를 사실처럼 가르쳐 placeholder보다 나쁘다**(실측: codex가 존재하지 않는 로그인·diff 화면을 진짜처럼 그려낸 사례 — 버튼 배치·라벨이 실제와 다름). "재현 예시" 칩으로도 정당화 금지 — 청중은 칩을 안 읽고 화면을 진짜로 받아들인다.
- **취득 순서**: ① 사용자 제공(`projects/<name>/images/`) → ② playwright로 실제 앱·공식 docs **실물 캡처** → ③ 공식 docs 스크린샷 인용 → ④ 그래도 없으면 **점선 placeholder + 캡션**으로 자리 유지(재빌드 시 채움). 이미지 검색 전용 MCP는 없음 — 실물은 playwright·공식 docs가 정답.
- 실물 캡처는 캡션 없이 임베드(진실). **STOP 신호**: "스크린샷이 없으니 codex로 비슷하게 만들자"는 생각이 들면 멈추고 ②~④로.
