## 3. Findings by tier

### P1

**1. `github-dev:post-merge` — description is 1014 chars against a 1024 cap where the failure is silent.**
`plugins/github-dev/skills/post-merge/SKILL.md:3`. Codex 0.135 skips any skill whose `description` exceeds 1024 characters without an error, and Claude Code has no limit, so the violation would be invisible from the side most likely to notice it. Ten characters of headroom means one clarifying word removes this skill from Codex entirely. The longest description in the fleet by 89 chars; next is `project-init:wiring` at 925.
*Edit:* move the trailing Codex sub-step note (`Codex note — Serena/rules-forge/... are Claude-only and skip.`, 108 chars) into the body. That is body content by the branch test anyway — only the Codex branch reads it.

**2. `code-scout:brightdata-guide` claims the research branch that `research-orchestrator` owns.**
`plugins/code-scout/skills/brightdata-guide/SKILL.md:3`. The description says *"Prefer Bright Data over the agent's built-in web fetch / web search for internet tasks - any URL, web search, `scrape`, ... research, fact-checking."* In the architecture this skill is web-scout's **tier-3 fetch fallback**, reached when exa fails; `research-orchestrator` is the front door and explicitly routes away from its own siblings. A description claiming "any URL" plus "research" competes with the orchestrator on the orchestrator's own branch.
*Edit:* scope the opening to the condition that actually selects it — the MCP tools being absent from the registry (already stated later) or a failed primary fetch — and drop the "Prefer ... over built-in web fetch / web search ... research, fact-checking" clause. The site roster (Amazon / LinkedIn / Instagram / TikTok / YouTube / X / Reddit / Google Shopping) is body content.

**3. `ml-toolkit:edit-notebook` claims every `.ipynb` write, including the two that generate one.**
`plugins/ml-toolkit/skills/edit-notebook/SKILL.md:3` reads *"(3) any .ipynb file modification"*. Generating a notebook writes an `.ipynb`, so this collides head-on with `ml-toolkit:cv-notebook` ("CV notebook", "detection notebook", "train YOLO notebook") and `ml-toolkit:cv-explorer` ("exploration notebook", "interactive viewer").
*Edit:* restrict to an **existing** notebook and add the sibling pointers, matching the pattern the three `docs-forge:skill-*` descriptions already use: "For generating a new CV notebook use `ml-toolkit:cv-notebook`; for an exploration / viewer notebook use `ml-toolkit:cv-explorer`."

**4. `docs-forge:skill-audit` and `docs-forge:skill-fleet-review` carry the same six-row axis table, paraphrased, and it has already drifted.**
`skill-audit/SKILL.md:88-96` and `skill-fleet-review/SKILL.md:142-149`. Both bodies state that the rules "belong to `docs-forge:skill-forge` and live in its bundled references", then restate them anyway. The drift is live, not hypothetical: skill-audit's runtime-contract row includes *"a Hermes-eligible skill with no tool mapping"* and fleet-review's does not, so the same axis is defined differently depending on which skill you invoke.
*Edit:* extract one `plugins/docs-forge/skills/skill-forge/references/axes.md` holding all seven rows; both bodies point at it and keep only the loop cardinality that actually differs (one skill vs a cohort). Applied in this change — see section 6.

**5. `ml-toolkit:cv-explorer` is the only skill in the repository stored with CRLF line endings.**
`git ls-files --eol` reports `i/crlf w/crlf` for `plugins/ml-toolkit/skills/cv-explorer/SKILL.md` and its five `references/` files; every other skill is LF. `.gitattributes` pins `eol=lf` for `*.sh`, `*.mjs`, `*.py` and `.githooks/*` only — `*.md` is unmanaged, so nothing normalizes this and nothing detects it.
Impact is bounded and partly `unverified`: `check-skill-contract.mjs` parses it, and the skill loads under Claude Code, so this is not a confirmed silent failure on any runtime. What is confirmed is that any shell a reader lifts out of these files carries a trailing `\r`, and that the fleet is inconsistent 1-in-53.
*Edit:* add `*.md text eol=lf` to `.gitattributes` and renormalize. The resulting diff is exactly these six files, since they are the only CRLF markdown in the tree.

*Edit:* delete the eleven entries that duplicate an in-body pointer. Keep lines 647-648 (`plugins/github-dev/docs/coderabbit-config.md` and the external `coderabbitai/skills` repo), which are the only two pointing at something the body never names.

**7. `version:` in skill frontmatter has no statable runtime effect.**
`docs-forge/interview-methodology:4` (`0.4.0`), `docs-forge/voice-prompt:4` (`0.1.0`), `llm-wiki/plaud-note-taking:4` (`0.2.0`). Plugin versions live in `plugin.json` + `marketplace.json` and are what the cache and the guards read; a skill-level `version:` is read by no runtime and by no script in this repo, and all three are already stale relative to their plugin's version. Three of 53 skills carry it, which is the definition of a field nobody can state an effect for.
*Edit:* remove the field, or state its purpose in `references/frontmatter.md` if one exists. Deferred — needs the frontmatter reference consulted first, and it touches three plugins.

**8. `allowed-tools` is present on 15 of 53 skills with no principle behind the split.**
`e2e-harness` 3/3 and `github-dev` 8/9 carry it; `llm-wiki` 0/6, `ml-toolkit` 0/6, `code-scout` 0/4, `mem0-ops` 0/3, `project-init` 0/2 do not. Whether it is load-bearing (a real permission narrowing) or decorative cannot be told from the distribution.
*Edit:* decide one way in `references/frontmatter.md`, then make the fleet consistent. Deferred — a fleet-wide frontmatter change needs its own change and bumps.

**9. `license: MIT` on exactly one skill.**
`plugins/code-scout/skills/brightdata-guide/SKILL.md:5` — the only `license:` in 53 skills, a remnant of this skill's origin as its own plugin before PR #200 absorbed it. No runtime reads it.
*Edit:* remove.

**10. Redundant Korean trigger pair.**
`code-scout:research-orchestrator` lists both `"조사해줘"` and `"조사"`; the second subsumes the first. Trivial, but it is permanent context in a 897-char description.

**11. `llm-wiki:plaud-note-taking` owns a phrase that belongs to another skill.**
Its description says it *"relentlessly interviews the user (grill-me)"*, and `docs-forge:interview-methodology` lists `"grill me"` / `"집요하게 캐물어"` as its own triggers. plaud delegates to interview-methodology, so it should name the delegation rather than the trigger phrase.

**12. Four `docs-forge` guide skills describe a subject instead of a reaching condition.**
`changelog-guide`, `deploy-doc-guide`, `moc-guide`, `readme-guide` all follow the shape *"X reference — ... Loaded by the docs-forge Y workflow."* No "use when", no triggers. This is arguably correct for a skill that is only ever loaded by a sibling, but under Claude Code and Codex they are still indexed as directly invocable, so a user asking "how should I write a changelog" reaches nothing. Flagged rather than fixed: the right answer depends on whether these are meant to be user-reachable at all, which is a design decision, not a defect.

Three over-engineering claims that motivated this sweep were **refuted by measurement** and must not be carried forward:

| Claim | Measurement |

| 11 untested scripts, delete the ones with zero call sites | No script has zero call sites. The finding reduces to "11 scripts lack tests", whose highest-value target is `probe-codex-engagement.sh` — 6 call sites, 0 tests |
